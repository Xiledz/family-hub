Part 2 — The seed block~10 min

Understand it, then run the schema
Open supabase/schema.sql and scroll to the bottom
Look for the line -- SEED — ALREADY FILLED IN, roughly 3/4 of the way down. Everything above it is table definitions — do not touch those. The seed block is the only part describing your family, and it is these ten lines:
insert into households (id, name, passcode, timezone) values
  ('00000000-0000-0000-0000-000000000001', 'Kelley Family', 'KELLEY2009', 'America/Chicago');

insert into members (household_id, name, color, role, sort_order, default_lead_minutes) values
  ('00000000-0000-0000-0000-000000000001', 'Erich', '#2f6f5e', 'owner', 1, 30),
  ('00000000-0000-0000-0000-000000000001', 'Jess',  '#b4553c', 'adult', 2, 30),
  ('00000000-0000-0000-0000-000000000001', 'Addie', '#7d4a8c', 'teen',  3, 15),
  ('00000000-0000-0000-0000-000000000001', 'Bryce', '#37588f', 'child', 4, 15);
That long repeated number is the household ID. It's identical on every line on purpose — it's the column that says "this person belongs to that household." Leave it alone; it's also hard-coded in config.js and the calendar feed URL.
Know what each field controls
Reading left to right on a member line:
nameMust match how people will type it in the quick-add bar. "Soccer Thursday 5:30 Addie" only works because the name is Addie. Use the name everyone actually says out loud, and keep it one word.
colorThat person's stripe on every event, their dot in the week strip, their chip in the Who picker. Already contrast-checked against each other in light and dark mode.
roleowner · adult · teen · child. Only owner and adult will ever see the Money module. This is the one field worth thinking twice about — changing it later means hand-editing the row.
sort_orderOrder names appear in the "Who's using this phone?" list. Cosmetic.
leadThat person's standing reminder in minutes. 30 means "always warn me 30 minutes before" so they never pick one per event. They can still override it on any single event.
Erich · green Jess · terracotta Addie · purple Bryce · blue
Decide: is Addie a teen or an adult?
Right now Addie and Bryce are both locked out of the future Money module. If you'd want Addie to see household finances someday, change her role to adult now — it costs nothing today and saves an awkward migration later. If not, leave it.
Roles do nothing at all in v1 — everyone sees the same calendar. They only start mattering when the Money module gets built. You're setting it now purely so you never have to retrofit it.
Optional: add a fifth person
Copy any member line, change the name, pick a color, and give it the next sort_order. Watch the punctuation — every line ends with a comma except the last one, which ends with a semicolon. That's the single most common way this fails.
  ('00000000-0000-0000-0000-000000000001', 'Grandma', '#8a6d2f', 'adult', 5, 60);

Part 3 — Notification keys~4 min

Generate the push keys — no install needed
Double-click vapid-keys.html
Click Generate keys. They're created by your browser's own crypto, on your machine — nothing is uploaded and nothing gets installed. Leave the page open until you've pasted everything; refreshing makes a different pair.
This replaces the npx web-push command. That failed because Node isn't installed on this PC. You don't need it for this step.
Add four secrets in Supabase
Dashboard → Edge Functions → Secrets → Add new secret. Four separate entries. Each one has a Copy button on the keys page — use it, don't retype.
VAPID_PUBLIC_KEY   (long one, ~87 characters)
VAPID_PRIVATE_KEY  (short one, ~43 characters)
VAPID_SUBJECT      mailto:erich.kelley@gmail.com
HOUSEHOLD_ID       00000000-0000-0000-0000-000000000001
The private key goes here and nowhere else — never in config.js, never in the repo. Names must match exactly, including underscores.
Put the public key in config.js
Open config.js in Notepad, find the line VAPID_PUBLIC: '', and paste the long public key between the two quotes. Leave SMS_ENABLED as false. Save.
The single most common way this breaks: the public key in config.js and the private key in Supabase come from different runs of the generator. They're a matched pair — mixed pairs fail silently, with no error anywhere.

Part 4 — Server functions~10 min

Deploy the reminder engine
Install Scoop, then the Supabase CLI
Since Node isn't on this machine, use Scoop — it's the method Supabase actually documents for Windows, and it doesn't need Node at all. Open PowerShell (not Command Prompt) and run these one block at a time.
1. Install Scoop — skip if you already have it:
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Invoke-RestMethod -Uri https://get.scoop.sh | Invoke-Expression
2. Install the Supabase CLI:
scoop bucket add supabase https://github.com/supabase/scoop-bucket.git
scoop install supabase
3. Confirm it worked:
supabase --version
Prefer to install Node instead? Grab the LTS installer from nodejs.org, accept the defaults, then close and reopen your terminal — that last part is what people miss. After that npx supabase <command> works in place of supabase <command> everywhere below. Note that a plain global npm install -g supabase is no longer the supported route.
